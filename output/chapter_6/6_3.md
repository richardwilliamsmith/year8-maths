### Key Vocabulary
- **Algorithm**: A precise, finite sequence of step-by-step instructions designed to solve a mathematical problem or perform a calculation.
- **Trace Table (Desk-Checking)**: A structured table used to manually test an algorithm step by step, recording the value of each variable after every instruction or loop iteration to verify correctness or locate errors.
- **Logic Error (Bug)**: A flaw in the design of an algorithm or formula (such as missing brackets, an incorrect inequality sign, or an off-by-one loop condition) that causes the algorithm to produce an incorrect output.
- **Iteration**: The repetition of a block of instructions in an algorithm (a loop) until a specified stopping condition is met.

## Theory & Key Ideas

### Representing Algebraic Algorithms: Pseudocode and Flowcharts

An algorithm takes one or more **inputs**, applies a sequence of well-defined mathematical operations (**sequence**, **selection/branching**, and **iteration/loops**), and produces an **output**. In flowcharts, ovals represent Start/End terminals, parallelograms represent Input/Output, rectangles represent Processes (assignments such as $y \leftarrow 3x - 2$), and diamonds represent Decisions (yes/no conditions such as $x \le 5$).

$$\text{Input } x \longrightarrow \text{Process: } y \leftarrow mx + c \longrightarrow \text{Decision / Loop} \longrightarrow \text{Output } y$$

> **💡 Assignment Updates the Variable**
> The instruction $x \leftarrow x + 2$ (or `x = x + 2` in code) is not an algebraic equation to solve — it means 'take the current value of $x$, add $2$, and store the result back into $x$'.

### Desk-Checking with Trace Tables

To verify whether an algorithm works as intended, mathematicians and programmers perform a **desk-check** by constructing a **trace table**. Each column represents a variable or condition check, and each row records the updated state of those variables as you step through the algorithm line by line with known test inputs.

$$\text{Iteration } k: \quad x_k = x_{k-1} + \Delta x, \qquad y_k = m x_k + c$$

> **💡 Test Boundary and Extreme Cases**
> Always desk-check an algorithm using at least three types of test data: a standard positive value, zero or a negative value, and the exact boundary value where a decision condition changes.

### Linear Rule-Generation Algorithms and Iterative Routines

A loop can generate a table of values for a linear relation $y = mx + c$ either by substituting $x$ at each step or by starting at $y_0 = c$ and repeatedly adding the constant first difference $m$ each time $x$ increases by $1$. Iterative algorithms can also search for solutions (such as finding when a linear cost model first exceeds a budget) by incrementing $x$ until a target condition is satisfied.

$$\text{Start } (x, y) = (0, c); \quad \text{Repeat: } x \leftarrow x + 1, \; y \leftarrow y + m$$

> **💡 Order of Updates Inside a Loop Matters**
> In a loop, updating $x \leftarrow x + 1$ before calculating $y \leftarrow mx + c$ produces a different pair of values than calculating $y$ first and incrementing $x$ afterwards.

### Debugging Order-of-Operations and Boundary Bugs

Two of the most frequent bugs in algebraic algorithms are: (1) **Order-of-operations bugs**, where a multi-term numerator or denominator is written inline without brackets (e.g. writing `y = 2*x + 6 / 2` instead of `y = (2*x + 6) / 2`), and (2) **Off-by-one boundary bugs**, where a strict inequality ($<$) is used instead of a non-strict inequality ($\le$), causing a loop to stop one step too early or too late.

$$\frac{a + b}{c} \;\text{must be coded as}\; (a + b) / c, \quad \text{never}\; a + b / c = a + \frac{b}{c}$$

> **💡 Compare Trace Output Against Known Mathematical Truth**
> To isolate a bug, calculate the true mathematical result by hand for a simple input (such as $x = 2$), compare it with each step of the trace table, and pinpoint the exact line where the two diverge.

### WE6_3_2: Identifying and Correcting an Order-of-Operations Bug in a Formula Algorithm

**Problem**: A student writes an algorithm to convert a temperature from degrees Fahrenheit ($F$) to degrees Celsius ($C$), where the true mathematical formula is $C = \frac{5(F - 32)}{9}$. The student's algorithm is:
- Step 1: Input $F$
- Step 2: Calculate `C = 5 * F - 32 / 9`
- Step 3: Output $C$
(a) Desk-check the student's algorithm using the test input $F = 68$ and compare it with the true Celsius temperature. (b) Identify the two errors in Step 2 and write the corrected instruction.

| Step | Thinking | Working |
| :---: | :--- | :--- |
| 1 | Evaluate the student's Step 2 at $F = 68$ using standard order of operations (multiplication and division before subtraction), and evaluate the true formula at $F = 68$. | $$\text{Student's code: } C = 5 \times 68 - \frac{32}{9} = 340 - 3\frac{5}{9} = 336\frac{4}{9}^\circ\text{C} \approx 336.44^\circ\text{C}$$
$$\text{True formula: } C = \frac{5(68 - 32)}{9} = \frac{5 \times 36}{9} = \frac{180}{9} = 20^\circ\text{C}$$ |
| 2 | Because multiplication and division have higher precedence than subtraction, `5 * F - 32 / 9` multiplies $5$ by $F$ alone and divides only $32$ by $9$. Brackets are needed around $(F - 32)$. State the corrected line. | $$\text{Corrected Step 2: } \texttt{C = 5 * (F - 32) / 9}$$ |

**Answer**: (a) Student's algorithm outputs $336\frac{4}{9}^\circ\text{C}$ instead of the true value $20^\circ\text{C}$; (b) Missing brackets around $F - 32$ caused $5$ to multiply $F$ only and $32$ to be divided by $9$ before subtraction. Corrected instruction: `C = 5 * (F - 32) / 9`.

## ⚠️ Common Misconceptions Alert

### Omitting Brackets Around Numerators and Denominators in Code
- **The Misconception**: Writing a fraction $\frac{x + 8}{4}$ in an algorithm or spreadsheet as `x + 8 / 4`, assuming the horizontal fraction bar is automatically implied.
- **The Correct Concept**: On a single line of code or spreadsheet formula, division (`/`) has higher precedence than addition (`+`), so `x + 8 / 4` is evaluated as $x + \frac{8}{4} = x + 2$. Parentheses must enclose any multi-term numerator or denominator: `(x + 8) / 4`.
- **❌ Incorrect Working**: $$\text{For } x = 12: \quad \texttt{12 + 8 / 4} = 12 + 2 = 14 \quad \text{(Incorrect)}$$
- **✅ Correct Working**: $$\text{For } x = 12: \quad \texttt{(12 + 8) / 4} = \frac{20}{4} = 5$$
- **Counter-Example**: At $x = 12$, $\frac{12 + 8}{4} = 5$, whereas `12 + 8 / 4` gives $14$.

### Treating Assignment Statements as Symmetric Algebraic Equations
- **The Misconception**: Thinking that the sequence of instructions $a \leftarrow b$ followed by $b \leftarrow a$ swaps the values of $a$ and $b$.
- **The Correct Concept**: Each assignment overwrites the target variable immediately. Once $a \leftarrow b$ executes, the original value of $a$ is lost and both variables hold the old value of $b$. Swapping two variables requires a third temporary variable (`temp`).
- **❌ Incorrect Working**: $$\text{Start } a = 7, b = 10: \quad a \leftarrow b \implies a = 10; \quad b \leftarrow a \implies b = 10 \quad (\text{Both equal } 10!)$$
- **✅ Correct Working**: $$\text{Start } a = 7, b = 10: \quad \text{temp} \leftarrow a \;(7); \quad a \leftarrow b \;(10); \quad b \leftarrow \text{temp} \;(7)$$
- **Counter-Example**: Without a temporary variable, $a$ and $b$ end up with identical values ($10$ and $10$) instead of being swapped to $(10, 7)$.

<details>
<summary><strong>Full Step-by-Step Solution</strong></summary>

**Final Answer**: (a) $y = 33$, (b) $y = 6x - 3$

#### Question `6_3_Q2` [Easy] *(Fluency)*

</details>

#### Question `6_3_Q4` [Medium] *(Error-Testing)*
A student codes the formula for the area of a trapezium $A = \frac{(a + b)h}{2}$ as `A = a + b * h / 2`. (a) If $a = 6, b = 10$, and $h = 4$, what number does the student's code output? (b) What is the true area of the trapezium, and how should the code be corrected?

<details>
<summary><strong>Full Step-by-Step Solution</strong></summary>

**Final Answer**: (a) $26$, (b) True area $= 32$; corrected code: `A = (a + b) * h / 2`

#### Question `6_3_Q5` [Medium] *(Cinema Ticketing Algorithm)*
A Melbourne cinema kiosk algorithm calculates the total price $C\text{ (\$)}$ for $n$ tickets at $\$16$ each plus a flat booking fee of $\$4$. If a group buys $5$ or more tickets ($n \ge 5$), a discount of $\$10$ is subtracted from the total bill. (a) Write the algebraic rule for $C$ when $n < 5$ and when $n \ge 5$. <details>

**Final Answer**: (a) If $n < 5$: $C = 16n + 4$; if $n \ge 5$: $C = 16n - 6$. (b) For $n = 4$: $\$68$; for $n = 5$: $\$74$

#### Question `6_3_Q8` [Challenging] *(Numerical Approximation Algorithms)*
Heron's iterative algorithm for approximating $\sqrt{N}$ updates an initial guess $x_0$ using the rule $x_{1} = \frac{1}{2}\left(x_0 + \frac{N}{x_0}\right)$. #### Question `6_3_Q9` [Medium] *(Debugging Algebraic Formulas)*
An algorithm is designed to find the $x$-intercept of the linear relation $y = mx + c$ (where $m \ne 0$). A student writes the steps: Step 1: Input $m$ and $c$. Step 2: Set `x_int = c / m`. Step 3: Output `x_int`. Test this algorithm on the line $y = 4x - 20$ and explain the mathematical sign error in Step 2.

<details>
<summary><strong>Full Step-by-Step Solution</strong></summary>

1. At the $x$-intercept, $y = 0$, so $0 = 4x - 20 \implies 4x = 20 \implies x = 5$. However, with $m = 4$ and $c = -20$, `c / m` outputs $\frac{-20}{4} = -5$.
2. Solving $0 = mx + c$ algebraically yields $x = -\frac{c}{m}$. The student forgot to negate $c$ when transposing it across the equals sign.

**Final Answer**: For $y = 4x - 20$ ($m = 4, c = -20$), the student's code gives $\frac{-20}{4} = -5$, whereas the true $x$-intercept is $x = 5$. Setting $0 = mx + c$ gives $mx = -c \implies x = -\frac{c}{m}$, so Step 2 is missing a negative sign (`x_int = -c / m`).
</details>

#### Question `6_3_Q10` [Medium] *(Sequence Sensitivity in Algorithms)*
Compare the following two loop bodies, both starting with $x = 1$ and $y = 10$:
- **Algorithm A**: (1) $x \leftarrow x + 2$, (2) $y \leftarrow 3x$
- **Algorithm B**: (1) $y \leftarrow 3x$, (2) $x \leftarrow x + 2$
After **one** pass through each algorithm, what are the values of $(x, y)$ in Algorithm A and in Algorithm B? Explain why they differ.

<details>
<summary><strong>Full Step-by-Step Solution</strong></summary>

1. In Algorithm A: first $x \leftarrow 1 + 2 = 3$, then $y \leftarrow 3(3) = 9$, giving $(3, 9)$.
2. In Algorithm B: first $y \leftarrow 3(1) = 3$, then $x \leftarrow 1 + 2 = 3$, giving $(3, 3)$. The order of sequential assignments changes which value of $x$ is substituted into $3x$.

**Final Answer**: Algorithm A produces $(3, 9)$; Algorithm B produces $(3, 3)$. In Algorithm A, $x$ is updated to $3$ before $y = 3x$ is evaluated; in Algorithm B, $y = 3x$ uses the old value $x = 1$ before $x$ is incremented.
</details>

#### Question `6_3_Q11` [Challenging] *(Debugging Loop Conditions and Step Sizes)*
A programmer writes a loop to sum all multiples of $5$ from $5$ to $50$ inclusive:
1. Set $n \leftarrow 5$ and $\text{sum} \leftarrow 0$.
2. While $n < 50$, repeat:
   (a) $\text{sum} \leftarrow \text{sum} + n$

#### Question `6_3_Q12` [Extension] *(Iterative Number Theory Algorithms)*
Consider the Collatz-style step rule applied to a positive integer $n$: **If** $n$ is even, $n \leftarrow \frac{n}{2}$; **Else** ($n$ is odd), $n \leftarrow 3n + 1$. Starting from $n = 7$, trace the sequence of values until $n$ first reaches $16$, and state how many steps it takes to reach $1$ from $n = 7$.

<details>
<summary><strong>Full Step-by-Step Solution</strong></summary>

1. Trace from $7$: $7 \to 22 \to 11 \to 34 \to 17 \to 52 \to 26 \to 13 \to 40 \to 20 \to 10 \to 5 \to 16$ ($12$ steps).
2. From $16$, four halving steps reach $1$: $16 \to 8 \to 4 \to 2 \to 1$, giving $12 + 4 = 16$ steps in total.

**Final Answer**: Path to $16$: $7 \to 22 \to 11 \to 34 \to 17 \to 52 \to 26 \to 13 \to 40 \to 20 \to 10 \to 5 \to 16$ ($12$ steps to reach $16$), then $16 \to 8 \to 4 \to 2 \to 1$ ($16$ steps in total to reach $1$)
</details>
